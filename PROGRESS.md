- Backup: `super-notes-backup` version 1, ZIP manifest и вложения (guard ≤100MiB), внутренняя `WaveNotes.backup` и staged `WaveNotes.backup.pending` через `Directory.Data`; на Save/закрытии редактора, НЕ при каждом вводе. При восстановлении отличающийся контент и reminder-only изменение создают отдельный вариант, текущая версия не затирается. `recoveredVersionId` — НЕ шифрование/криптографическая подпись.
- Обмен: `.wnote` (`wave-notes-single` v1) ≤80MiB, JSON manifest + media, строгая валидация, неразрушающий импорт. Не принимать произвольный ZIP и не принимать частичные бинарники.
- Редактор: Tiptap/ProseMirror, custom `waveChecklistItem` / `wavePageBreak` / fold/drawing/quote/tape; групповые операции одной транзакцией сохраняют marks и Undo. Страницы **списка папки №10** и **страницы документа №27** разные механизмы.
- OCR: камера/галерея → bundled offline ML Kit Latin/Chinese/Japanese/Korean/Devanagari + Tesseract `kaz+rus` → merge/dedupe/recovery → **сохранение обычной заметки** → только потом навигация редактора. Не переводить, не заставлять выбирать язык; не смешивать с PDF-редактированием.
- Реклама: Native AdMob/UMP (может требовать интернет); слот первым элементом и далее после каждых **5 пользовательских** записей, высота карточки около 120, label «Реклама»; не вставлять под системные панели, согласие не спрашивать повторно без оснований, не убирать рекламный функционал ради «оптимизации».
- Защита: PIN/биометрия — ограничение входа, **не сквозное шифрование локального содержимого**; при описании политики не обещать криптографическое шифрование.
- Telegram: только «Настройки → Ваши пожелания» отправляет собственные введённые тему и сообщение; пользовательский Telegram не нужен. Работоспособность доставки была подтверждена владельцем в прошлой беседе. **В актуальном Java-коде присутствует встроенный секрет — P0**, хотя документация архитектурно описывает relay. Не менять направление доставки без проверки.

## 5. Архитектурные решения — что НЕ ломать

### 5.1 Долговечность пользовательских данных

1. **Persist then publish:** `src/lib/notes-store.ts` пишет в `sn.notes.v1` до React `commit/emit`. Запрещено показывать успешный Save при отказе localStorage/IDB. При изменении другим окном проверяется старый raw snapshot; обнаруженный конфликт не перезаписывается.
2. **Бинарники отдельно:** фото `image-files.ts`, аудио `audio-files.ts`, PDF `pdf-files.ts`, ссылки на ID хранятся в HTML/metadata. Не вставлять огромные base64 в localStorage, не удалять shared IDs до подтверждения сохранённого состояния; cancellation/failed Save должен чистить только newly created unused blobs.
3. **Восстановление только после валидации:** `backup.ts` и `local-backup.ts` проверяют формат, entries, размер, refs, staged файл; копии должны MERGE, а не стирать свежие заметки. Новые версии при изменённом reminderAt/reminderRepeat, legacy absent поля не должны менять fingerprint старых копий. Реальные файлы проверить на версии 1 и совместимость с прежними.
4. **.wnote импорт:** отдельный формат, максимальный размер 80MiB, строго ограниченный manifest/IDs; вложения импортируются атомарно, не заменяя существующий экземпляр. Нельзя открывать любой ZIP как доверенную заметку.
5. **Каждое изменение документа — одно Undo:** Tiptap/ProseMirror транзакции в `wave-block-motion.ts`, `wave-page-actions.ts`, `wave-checklist-actions.ts`; сохранять inline marks, page dividers и binary IDs.
6. **Backup lifecycle:** событие dirty только на настоящем Save/подтверждённой операции, а не во время печати; авто-копия не должна блокировать UI. Внутренняя копия в Directory.Data, удалится при uninstall. Не заявлять обратного.
7. **PIN:** gate UI, не шифрование текста. Долговечность данных важнее успешного всплывающего toast.

### 5.2 OCR поток и принятие результатов

`src/routes/camera.tsx` (Camera/Photos) → `src/lib/ocr-plan.ts` (план всех поддерживаемых офлайн скриптов) → ML Kit + Android `OfflineCyrillicOcrPlugin`/Tesseract → `ocr-hybrid.ts` / `ocr-merge.ts` (координаты и дедупликация) → `ocr-partial.ts`/`ocr-draft.ts` (сохранить частичный текст/предупреждения/восстановление) → `ocr-save-flow.ts` (сначала сохраняет заметку) → `/editor/$id`.

- Поддерживать Latin, Chinese, Japanese, Korean, Devanagari через локальные ML Kit model deps и Cyrillic (RU/KK) через bundled Tesseract, работа без сети. `ocr-plan.ts` фиксирует порядок `latin,cyrillic,japanese,chinese,korean,devanagari`, пакет `kaz+rus`.
- Не смешивать японский и китайский по одним иероглифам без подтверждения. Не терять повторяющиеся строки. При неоднозначности/неполном проходе показывать предупреждение и дать восстановить по тому же фото, не удаляя уже распознанное.
- Не начинать одновременно второй native-скан камеры поверх первого; предусмотреть ошибки разрешений, пропавший picker, большой документ и недостаток памяти.
- **Отдельные пользовательские режимы:** OCR -> заметка; PDF -> ручной PDF editor. Это явно закреплено в `README.md` и `bun scripts/test-feature-boundaries.ts`.

### 5.3 Android, реклама, разрешения, производительность

- `MainActivity.java`/`SystemUiInsets.java` — единый владелец системных insets; React не должен ещё раз накладывать status/navigation padding. Проверять 3-button, жесты, keyboard, тёмную/светлую тему, 7 разных размеров в CI.
- Не подвешивать WebView тяжёлыми синхронными OCR, декодированием полной аудиодорожки и massive JSON/reflow. Для крупных операций разбивать работу и использовать watchdog/cancel, но **не отключать функции**.
- Splash анимировать через мягкий light/fog opacity и лёгкие трансформации без дорогих живых blur/clip path; watchdog 5,2 с по `docs/wave-notes-premium-intro.md`.
- AdMob Native + UMP: визуальный слот не должен ломать ленту/выбор/scroll; повторно использовать согласие, не делать ложных запросов и не терять метку «Реклама».
- Сохранённая тема заметки независима от текущего light/dark; бумага `note-paper.ts` только визуальные фон/линии и никак не меняет содержимое. По умолчанию жёлтый фон только новой заметки.
- Офлайн документ/сканирование != «все функции офлайн»: реклама, Telegram и политика приватности относятся к сетевым операциям.

### 5.4 Telegram feedback — критическое несоответствие источников

**Подтверждено просмотром актуального кода:** в `android-overlay/app/src/main/java/app/lovable/supernotes/TelegramFeedbackPlugin.java` есть статическая строка с бот-токеном и прямой вызов Telegram API. Значение НЕ сохранять, не печатать и не показывать в чате. `android-overlay/app/build.gradle` одновременно содержит настройку `WAVE_FEEDBACK_RELAY_URL`, `feedback-relay/index.mjs` содержит код HTTPS relay, а `docs/wave-notes-telegram-feedback.md` ошибочно утверждает, что Android-клиент уже без секрета. **Текущее обещание «token-free APK» недоказано и конфликтует с Java-кодом**; успешно собранный APK не равен секретно-безопасному APK.

План исправления без потери работающего фидбэка: проверить actual codepath/сборку → безопасно подключить реально развёрнутый HTTPS relay с секретом только в серверной среде → валидировать доставку на тестовом окружении и через ACK → убрать прямой fallback/секрет из исходника и APK → ротировать ранее засвеченный токен через владельца Telegram и проверить реальную доставку → актуализировать документацию и внешнюю политику. **Не ротировать/не удалять действующий токен до проверенного альтернативного пути, не требовать от пользователя выкладывать токен в чат.** Если нет доступа к Cloudflare/Telegram — пометить этот внешний шаг отдельно, продолжать остальные безопасные задачи; риску присвоить P0 до исправления. Переписывание GitHub истории без разрешения запрещено; простое удаление строки из нового коммита не удаляет токен из истории, поэтому ротация необходима.
